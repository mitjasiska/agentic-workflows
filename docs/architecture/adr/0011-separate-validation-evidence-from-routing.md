# Separate validation evidence from workflow routing

AW records tests, linting, type checking, and other checks as Validation Evidence without treating every failure as an automatic workflow stop. A failure caused by the proposed change keeps the Implementer working until the relevant check succeeds or a genuine human decision is required. A failure the Implementer classifies as pre-existing or otherwise unrelated remains failed evidence and produces a prominent non-blocking user warning, but AW automatically continues to independent review when the requested work is otherwise complete. The Implementer may investigate enough to support that classification but does not modify unrelated tests or functionality merely to clear the warning; doing so requires existing Task scope or explicit authorization. The Reviewer receives the evidence and independently decides whether it demonstrates an actionable defect or a visible limitation. A clean Review Report that accepts the limitation remains ordinary clean-review evidence for normal `awctl pr`; it needs neither another acknowledgement nor `--force`, while the limitation stays visible in review and submission reporting. Broad suites that may contain thousands of tests and take hours are user-scheduled rather than default implementation, review, or PR gates. v1 does not add separate deterministic lint or type-check phases. A later project-configured deterministic validation pipeline after the final review remains an extension seam whose failure semantics must be decided separately. This preserves truthful evidence and unattended progress while avoiding both the prototype's mandatory escalation and unauthorized scope growth.
