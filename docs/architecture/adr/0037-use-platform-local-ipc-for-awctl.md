# Use platform-local IPC for awctl

The JSON envelope Design Direction is refined to JSON-RPC 2.0 with separate application versioning by [ADR 0038](0038-adopt-json-rpc-for-local-control.md). The local transport, access, and Operation ownership boundaries below remain in force.

`awctl` is a co-located administrative client for one AW control plane and uses a small structured JSON request/reply protocol over platform-local IPC rather than the dashboard HTTP API. Linux and macOS use a Unix-domain socket, while Windows uses a named pipe; both adapters restrict access to the operating-system account running the control plane and are selected automatically without remote endpoint configuration or discovery. Exchanges are bounded: mutating requests return after durable acceptance or completion of their immediate action, while longer-running Operations remain owned by the control plane and survive CLI exit or disconnection. Every exchange identifies its protocol version and returns a structured result or diagnostic; pre-stable builds accept only the matching current version and provide explicit update or restart guidance on mismatch instead of negotiating compatibility. The React dashboard remains the supported client of the separate control-plane HTTP interface hosted by the same process. Both presentation adapters invoke the same application commands and queries, preserving one workflow implementation while avoiding v1 network administration, authentication, and compatibility machinery. A future remote or distributed administration model requires an explicit architecture decision and can add another adapter at the same application seam.
