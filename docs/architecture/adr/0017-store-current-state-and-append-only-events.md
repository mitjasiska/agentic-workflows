# Store current state and append-only events

SQLite stores explicit current workflow state alongside the append-only Workflow Audit Trail. Each successful application command updates the affected current-state records and appends its historical events atomically in one transaction. Every event receives a monotonically increasing position within its Workflow in that transaction. The position is authoritative for workflow-local ordering; timestamps are informational. AW does not impose a global causal order on events from independent concurrent Workflows. Cross-Workflow views may use recorded time and a stable tie-breaker for deterministic presentation only. For agent completion, that transaction also stores the complete validated JSON Result Envelope, its typed relational projection, and any pending intent for the next external action. The envelope and projection are derived from one validated object and cannot be edited independently. Dashboard and workflow decisions query current state directly, while events explain how that state was reached. A workflow-history projection turns those records into stably ordered, meaningful steps with concise outcomes and links to detailed reports; later conclusions never erase earlier steps while the Workflow is retained. The Workflow is the referential-integrity and retention root for all run-specific current state and history. After applicable external teardown, cleanup deletes that complete owned record set atomically while preserving installation-level project/repository configuration and sibling Workflows; no pass, report, evidence, or event remains orphaned. AW does not reconstruct ordinary current state by replaying the complete event history. This provides efficient centralized queries and observability without the implementation and migration complexity of full event sourcing or a permanent project registry.
