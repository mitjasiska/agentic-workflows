# Make abandonment resumable and support Forced Cleanup

Abandoning a Workflow stops all automatic routing but preserves its managed worktree, sessions, snapshots, evidence, reports, history, and durable current state. It is neither a failure nor cleanup. The user may explicitly resume later, at which point AW revalidates current external and workspace state and exposes every applicable Attention Requirement before continuing.

Ordinary cleanup preflights its full deletion boundary and may stop when policy, unresolved Attention Requirements, uncommitted content, or local-only commits make deletion unsafe or ambiguous. It removes the exact local Workflow branch only when AW proves that no unique local work would be lost. A refusal leaves the retained Workflow intact and proposes the exact `awctl cleanup --force` command.

Forced Cleanup is an invocation-scoped destructive escape hatch. After resolving the exact Workflow and verifying both its managed-target and local-branch identities, AW asks Herdr for one bounded best-effort teardown of every owned process, pane, session, and worktree. Herdr may escalate from graceful interruption to forced process-tree termination before removing the worktree with its required local Git bookkeeping. AW then attempts to delete the exact verified local Workflow branch even when this discards local-only work. Open, idle, running, failed, unreachable, or otherwise uncertain execution state is input to the bounded attempt, never a precondition that prevents it.

Ordinary cleanup deletes AW state only after both teardown and local-branch deletion are confirmed. Forced Cleanup always deletes all local AW-owned state after its bounded attempts. Complete teardown and branch deletion return success. Any failed or unconfirmed component returns a structured partial-cleanup result and distinct non-zero exit code containing the last-known target, managed path, branch, component outcomes, and manual-cleanup details. If branch identity cannot be proven or deletion fails, AW preserves that branch rather than broadening the target. No AW retry remains because the Workflow state is gone. Forced Cleanup never bypasses immutable Workflow identity, resolved managed-path, branch-identity, or deletion-boundary verification, never broadens to sibling Workflows, and cannot be saved as a default.

Cleanup has no remote Git, forge, or Linear effects. It never changes a remote branch, rewrites or pushes remote history, closes or deletes a pull request, or changes Task status. Herdr owns session and managed-worktree teardown; AW owns only the narrowly bounded deletion of the verified local Workflow branch after it is no longer checked out. Neither component may mutate any other local ref or repository history.

If Herdr cannot complete or confirm forced teardown, the managed workspace or process may remain orphaned; if local-branch deletion cannot be confirmed, the branch may remain. AW does not pretend otherwise. It retains no Workflow-specific orphan record, tombstone, cleanup receipt, audit history, or other durable state after forced cleanup. Ordinary infrastructure logging follows the general logging policy and is not a recovery registry.
