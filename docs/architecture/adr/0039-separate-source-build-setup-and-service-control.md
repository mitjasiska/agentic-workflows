# Separate source build, source setup, and service control

Agentic Workflows keeps source compilation, source-checkout setup, and runtime service management as three explicit operations rather than making `awctl` build or implicitly install itself. Repository-root `build.sh` builds or tests the matching client and control plane; ownership-aware `setup-source.sh` configures the PATH launcher and enabled non-root `systemd` user service without building or starting it; and `awctl service start|stop|restart|status|enable|disable` manages only that configured local service. This preserves the established meanings of `awctl start TASK-ID` and `awctl status`, lets service commands work while the Local Control Interface is unavailable, and leaves packaged installation and update mechanics open until usage evidence justifies combining steps.

Service lifecycle never doubles as Workflow lifecycle. Start and restart verify Local Control Interface readiness, stop verifies the unit and owned socket are gone, and stop or restart may leave Herdr-owned executions running for later reconciliation. Repeated source setup for the same checkout is safe, conflicting launchers or units are not overwritten, and source-setup removal deletes only artifacts whose ownership is proven.
