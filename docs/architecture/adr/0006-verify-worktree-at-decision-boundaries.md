# Verify the worktree at decision boundaries

AW uses point-in-time content evidence instead of continuously watching the filesystem. A Git Review Target records the repository object format plus Git's own baseline and proposed tree identities rather than an AW-specific hash format. AW obtains a stable proposed-tree hash before review, compares it again after review, and checks it immediately before commit. A changed hash invalidates review authority or refuses submission; staging, unstaging, or committing identical content does not. Submission commits exactly the tree frozen in the durable PR Intent and verifies the resulting commit without disturbing the user's index. `--force` may bypass clean-review evidence but receives the same frozen-tree, race, ancestry, and target-safety guarantees. Superseded targets retain their identities and reports but are not pinned as permanently restorable source archives. The concrete capture, retry, and Git command sequence is Implementation Latitude; the prototype's private-index approach is one proven implementation.
