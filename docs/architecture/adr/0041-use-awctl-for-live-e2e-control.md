# Use awctl for live E2E control with read-only observations

The first owner-driven smoke test, and the later automated E2E runner, drive and query AW through ordinary `awctl` commands so the test exercises the installed product's CLI, Local Control Interface, workflow, and submission path. They may also inspect SQLite state and Herdr state or panes in read-only form to verify durable facts or diagnose a failure; keeping future kit code in the AW monorepo allows those schema-aware observations to evolve with the product. This combines the real user-facing path with useful internal evidence without making the SQLite schema a public integration contract or replacing AW's workflow authority.

Supporting observations never write or repair the database, synthesize a successful Result Envelope, mutate AW-owned Herdr resources behind the workflow, or publish through a substitute Git/forge path. Test-fixture preparation and independent provider verification remain outside AW's tested workflow, initially performed by the operator and later by a runner. The minimal scenario determines which observations are actually needed. The [E2E test-kit architecture](../e2e-test-kit.md) owns the detailed current design.
