# Run the v1 control plane as a systemd service

On Linux, v1 runs as a long-lived, non-root `systemd` user service under the same Unix account that owns Herdr sessions, Git credentials, and AW-managed workspaces. It starts automatically and is supervised across failures and machine restarts. It hosts the Local Control Interface, control-plane HTTP API, and React dashboard; owns SQLite access; dispatches durable pending operations; and reconciles Herdr executions after interruption. Managed workflows therefore do not depend on an interactive shell or a continuously running `awctl` process. Remote Herdr work may continue while the service is unavailable and is reconciled when the service returns. Ordinary `awctl` commands never silently start the service; an unavailable local IPC endpoint produces local service diagnostics and an explicit lifecycle command. The fixed `awctl service` namespace manages this local user service even when the control plane is stopped, while application commands and queries continue to use the Local Control Interface. `awctl` automatically uses the owner-only Unix-domain socket created by the co-located service and has no network endpoint configuration or discovery. Future Windows hosting uses an equivalent user-restricted named pipe and requires a platform-appropriate service host before Windows becomes officially supported. A dedicated organizational service account is deferred to v3, avoiding v1 filesystem and credential permission friction. [ADR 0039](0039-separate-source-build-setup-and-service-control.md) records the source-build, setup, and lifecycle command boundary.
