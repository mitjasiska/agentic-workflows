# Run the V1 control plane as a systemd service

On Linux, V1 runs as a long-lived, non-root `systemd` user service under the same Unix account that owns Herdr sessions, Git credentials, and AW-managed workspaces. It starts automatically and is supervised across failures and machine restarts. It hosts the control-plane API and React dashboard, owns SQLite access, dispatches durable pending operations, and reconciles Herdr executions after interruption. Managed workflows therefore do not depend on an interactive shell or a continuously running `awctl` process. Remote Herdr work may continue while the service is unavailable and is reconciled when the service returns. Ordinary `awctl` commands never silently start the service; an unreachable endpoint produces service diagnostics and an explicit lifecycle command. `awctl` uses one explicit endpoint, defaulting to loopback, and does not perform network discovery. Endpoint precedence is invocation-scoped `--server`, `AW_SERVER`, saved user configuration, then the loopback default; invalid higher-precedence values fail instead of falling back. Later coordinated replicas may stay behind that same logical endpoint. A dedicated organizational service account is deferred to V3, avoiding V1 filesystem and credential permission friction.
