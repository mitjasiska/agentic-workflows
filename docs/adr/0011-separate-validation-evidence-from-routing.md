# Separate validation evidence from workflow routing

AW records tests, linting, type checking, and other checks as Validation Evidence without treating every failure as an automatic workflow stop. An Implementer may fix and rerun a failing focused check within the same pass, and an unresolved failure may still proceed to independent review when no human decision is required; the Reviewer decides whether it demonstrates an actionable defect or a visible limitation. Broad suites that may contain thousands of tests and take hours are user-scheduled rather than default implementation, review, or PR gates. v1 does not add separate deterministic lint or type-check phases. A later project-configured deterministic validation pipeline after the final review remains an extension seam whose failure semantics must be decided separately. This preserves truthful evidence while avoiding the prototype's friction from coupling any reported failure to mandatory escalation.
