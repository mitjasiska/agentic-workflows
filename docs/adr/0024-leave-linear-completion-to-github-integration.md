# Leave Linear completion to the GitHub integration

v1 does not change a Linear Task to Done when `awctl pr` creates or updates a pull request. Pull-request creation is not completion: merge remains human-controlled, another reviewed batch may be added to the open request, and a Task may have sibling slice Workflows. The existing GitHub–Linear integration owns the Linear completion transition when the pull request is merged. AW may record and display the observed Linear status, but provider status is not evidence that AW review or submission state is valid.

To establish that integration link explicitly, `awctl pr` includes both the canonical Linear link and a deterministic closing reference such as `Fixes DEV-123` in the generated pull-request body's `Tracking` section for a Linear-backed Task. Every Whole Task or Named Slice pull request uses the same parent Issue key, allowing the integration to account for multiple linked requests. The reference is deliberately redundant with the Linear key already present in the branch name. Removing it requires a later explicit decision supported by evidence that branch-based linking alone is reliable. Dogfooding may supply evidence but does not alter the rule automatically.
