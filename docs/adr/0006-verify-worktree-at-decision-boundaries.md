# Verify the worktree at decision boundaries

AW uses point-in-time content evidence instead of continuously watching the filesystem. For Git work, the canonical Review Target records the repository object format plus Git's own baseline and proposed tree identities; AW does not maintain a parallel per-file hashing format. It constructs an uncommitted proposed tree through a private temporary index without changing or depending on the user's staging state. This preserves Git's semantics for paths, contents, deletions, modes, symlinks, and supported submodules. AW captures repository state before and after review to prove the Reviewer did not mutate it and compares the current materialized tree during `awctl pr` preflight. Review validity follows the exact tree content rather than a commit SHA, so staging, unstaging, or committing the identical tree does not require another review; Git identities remain separate ancestry, race, and remote-target safety evidence. Normal preflight binds matching clean-review evidence into a durable PR Intent, while `--force` may bypass that evidence requirement but still freezes the exact current content and verifies the target. This preserves deterministic review evidence without continuous-monitoring friction.
