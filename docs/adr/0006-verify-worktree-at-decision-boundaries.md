# Verify the worktree at decision boundaries

AW uses point-in-time content evidence instead of continuously watching the filesystem. For Git work, it constructs a complete Reviewed Tree from the comparison baseline and a Worktree Fingerprint, captures the repository state before and after review to prove the Reviewer did not mutate it, and compares the current materialized tree during `awctl pr` preflight. Review validity follows the exact tree content rather than a commit SHA, so staging, unstaging, or committing the identical tree does not require another review; Git identities remain separate ancestry, race, and remote-target safety evidence. Normal preflight binds matching clean-review evidence into a durable PR Intent, while `--force` may bypass that evidence requirement but still freezes the exact current content and verifies the target. This preserves deterministic review evidence without continuous-monitoring friction.
