# Use SQLite for the single v1 control plane

v1 stores authoritative AW-owned workflow data in one SQLite database per AW installation. That database spans all registered projects, repositories, workflows, and worktree records so the dashboard can provide centralized cross-project visibility and usage reporting. One AW service process hosts the single logical control plane, while Herdr may distribute agent execution across many machines. Multi-machine execution does not require a network database. PostgreSQL and speculative dual-provider support would add deployment and maintenance cost before AW has multiple database writers or a high-availability requirement. If a later company deployment introduces coordinated service replicas, PostgreSQL may be reconsidered; every replica would still share one central database and implement one logical workflow authority rather than several independent control planes.

Pre-stable builds intentionally support only their current database schema. Startup detects an incompatible schema before mutation and offers one explicit forced reset instead of migration or silent deletion. Reset archives the complete old SQLite database as a timestamped backup and initializes a fresh one. Users should clean active Workflows before a breaking upgrade; the new build never uses reset as permission to guess at or delete external Herdr resources it cannot prove it owns. Compatibility migrations are deferred until an explicit stabilization milestone.

Initial E2E uses a provisional local recovery policy: at most one verified, consistent SQLite backup per day, with the seven most recent daily backups retained separately from pre-reset archives. Detected corruption stops normal mutation and preserves the damaged database. Recovery requires one explicit restore command naming a verified compatible backup, followed by ordinary external-state reconciliation; AW neither repairs in place nor restores automatically. Same-machine backups do not constitute host-level disaster recovery. Backup cadence, retention, and off-machine recovery are intentionally revisited after operational experience.
