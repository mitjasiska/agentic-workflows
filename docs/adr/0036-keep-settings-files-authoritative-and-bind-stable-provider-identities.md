# Keep settings files authoritative and bind stable provider identities

AW has two authoritative human-edited configuration sources: one Global Configuration settings file for the installation and one Git-ignored Project Configuration TOML file in each Project's canonical registered checkout. SQLite stores the Project registration, configuration location, and last validated stable external identities for diagnostics, reconciliation, and Workflow creation, but it is not a third editable configuration source and never silently overrides the files. Managed worktrees locate the canonical Project file through their Workflow registration rather than receiving copied configuration. For settings that permit all levels, precedence is explicit invocation or next-pass choice, retained Workflow-level selection, Project Configuration, Global Configuration, then built-in default. Invalid higher-precedence values fail instead of silently falling back, and immutable Integration Binding identities are outside the ordinary override hierarchy. New Workflows use the newly validated settings, while retained Workflows preserve their immutable Integration Bindings. External relationships are bound by stable provider identities rather than display names, so renaming a Linear Project or another resource refreshes metadata without invalidating or deleting Workflow data. Selecting a different configured target affects new Workflows; a missing or replaced bound target stops only the affected action with recovery guidance. Cleanup always remains explicit.
