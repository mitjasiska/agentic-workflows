# Derive publication metadata from reviewed results

Linear-backed submission requires exactly one Primary Publication Category—`Feature`, `Bug`, `Chore`, `Docs`, or `Refactor`—to choose the deterministic `feat`, `fix`, `chore`, `docs`, or `refactor` prefix; orthogonal labels such as `Research` may coexist but do not affect the type. A clean Reviewer supplies public-safe summary, description, and validation fields from the exact reviewed result rather than copying the mutable Task title, and AW deterministically freezes `<type>: <summary> (<TASK-ID>)` as both commit subject and PR title, adds a `Task-Review` commit trailer, and constructs the sectioned PR body with the canonical Linear link and closing reference. Missing or ambiguous classification and missing, invalid, or stale reviewed metadata stop ordinary submission instead of guessing. This preserves the prototype's independently reviewed public metadata while retaining the successor's explicit GitHub–Linear closing link and protecting unrelated Linear labels.
