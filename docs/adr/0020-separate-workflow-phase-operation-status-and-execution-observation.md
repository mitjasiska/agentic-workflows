# Separate workflow phase, operation status, and execution observation

AW models Workflow Phase, Operation Status, and Execution Observation separately. The Initial E2E Workflow Phase set is exactly `WorkspacePreparation`, `Implementation`, `Review`, and `Submission`; readiness, submission evidence, retention, and cleanup are not phases. Submission is the umbrella for deterministic commit, push, and forge change-request creation or update, while merge remains separate. The Initial E2E Operation Status set is exactly `Pending`, `Running`, `Completed`, `Failed`, and `Interrupted`. User-requested stops and positively confirmed vanished executions are both `Interrupted` with distinct typed reasons; `Canceled` remains a Task-provider concept rather than another Operation Status. Semantic results such as review findings belong to the Result Envelope. AW stores no single authoritative Workflow Status or Outcome enum; current labels are projections of phase, operation and execution facts, active attention, abandonment, review eligibility, and submission evidence. A retained submitted Workflow may therefore return to `Implementation` without escaping a terminal state. Operation Status remains distinct from AW's timestamped last verified Herdr observation: recording start intent does not prove execution started, and an unreachable Herdr target does not prove execution stopped. AW retains the last confirmed observation and marks current reachability unavailable. It records `Interrupted` only after an explicit stop or positive reconciliation evidence. This separation avoids a combinatorial workflow-state enum and prevents missing external information from being converted into false certainty.
