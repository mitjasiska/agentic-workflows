# Make abandonment resumable and support Forced Cleanup

Abandoning a Workflow stops all automatic routing but preserves its managed worktree, sessions, snapshots, evidence, reports, history, and durable current state. It is neither a failure nor cleanup. The user may explicitly resume later, at which point AW revalidates current external and workspace state and exposes every applicable Attention Requirement before continuing.

Ordinary cleanup may stop when policy or unresolved Attention Requirements make deletion unsafe or ambiguous. `awctl cleanup --force` is instead an invocation-scoped destructive escape hatch. After resolving the exact Workflow and verifying its managed-target boundaries, AW asks Herdr for one best-effort forced teardown of every process, pane, session, and worktree owned by that Workflow. Herdr may escalate from graceful interruption to forced process-tree termination before removing the worktree with the required local Git bookkeeping. Open, idle, running, failed, unreachable, or otherwise uncertain execution state is input to that attempt, never a precondition that prevents it.

After the bounded Herdr attempt, AW always deletes all local AW-owned state for the selected Workflow. Complete teardown returns success. Any failed or unconfirmed external action returns a structured partial-cleanup result and distinct non-zero exit code containing the last-known target, managed path, and manual-cleanup details. No AW retry remains because the Workflow state is gone. Forced Cleanup never bypasses immutable Workflow identity, resolved managed-path, or deletion-boundary verification, never broadens to sibling Workflows, and cannot be saved as a default.

Cleanup has no remote Git, forge, or Linear effects. It never deletes branches, rewrites history, pushes, closes or deletes pull requests, or changes task status. AW itself invokes no `git` command during cleanup. AW requests session and managed-worktree teardown through Herdr, which owns the workspace and may perform the local Git worktree bookkeeping required to remove it safely. Ordinary cleanup deletes AW state only after the teardown result is durably known.

If Herdr cannot complete or confirm forced teardown, the managed workspace or process may remain orphaned; AW does not pretend otherwise. AW retains no Workflow-specific orphan record, tombstone, cleanup receipt, audit history, or other durable state after forced cleanup. Ordinary infrastructure logging follows the general logging policy and is not a recovery registry. This delegation grants neither component cleanup authority over project history, refs, remotes, forge state, or task state.
